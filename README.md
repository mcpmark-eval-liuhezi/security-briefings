# Security Briefings

Reference notes for the Java supply-chain security incidents that come up most often in our study group. Each briefing answers the same question — *"were our demo projects affected?"* — from written, sourced notes instead of memory.

Every briefing covers the CVE id, the affected version range, the first fixed version, the canonical upstream repository, and a short "what to check in your own project" section. Fix versions are cross-checked against the tags actually published by the upstream project before they land here: if a version does not exist as an upstream tag, it does not go in the notes.

Copy the structure of an existing briefing, keep the same sections, and cite the sources you relied on. Open a tracking issue first if the incident is likely to need follow-up research.
